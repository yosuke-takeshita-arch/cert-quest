# cert-quest 要件定義書

作成: 2026-10-02

## 1. 目的

会社で取得する2資格（G検定・DXビジネス検定）を、Android スマホで遊びながら**体系的に**学べるようにする。
Web の一問一答は知識が断片的になるため、**解説・誤答からの覚え方・用語のつながり**を厚くする。

## 3. 配布の形

- **PWA**（Web 技術で作り、Android の Chrome から「インストール」してホーム画面に置く。オフラインで動く）
- 資格ごとに**別アプリ**（アイコン2つ）。`g-kentei/` と `dx-biz/` がそれぞれ1つの PWA、共通部分は `shared/`
- 置き場所は GitHub Pages（2026-10-02 先生了承。URL を知る人は誰でも開けるため、会社の情報は入れない）
- 将来 APK に包み直せるよう、ビルド不要の素の HTML/CSS/JS で作る（フレームワーク・npm 依存なし）
- 学習記録は端末内（localStorage）。サーバーは持たない
- 全アプリが github.io の同じオリジンにあるため、Android の Chrome のメニュー「ホーム画面に追加」では2つ目以降を入れられない（同じオリジンにアプリが1つでもあれば「インストール済み」と判定される）。2つ目以降はホームの「アプリとしてインストール」ボタン（ページ側の案内）から入れる。manifest の id はアプリごとに重ならない値にする（2026-10-03）
- 画面の配色は設定で「明るい／暗い／スマホに合わせる」を選べる。初期は「明るい」（2026-10-03 先生決定）

### 3-2. 一般に配るために要る4つの機能（2026-10-04 先生決定）

**(1) 受験日を利用者が決める**
- 受験する回は人によって違う。受験日は `config.json` の `examDate` に固定せず、利用者が自分で決める（`config.json` の `examDate` は、聞くときの日付の初期値＝次の試験日の目安として使う）。
- 初回: タイトル画面の「タップしてはじめる」のあと、受験日がまだ決まっていなければ「受験日はいつですか」を聞く。日付を選ぶか「まだ決めていない」を選ぶ。あとで設定で変えられると一言添える。
- 設定画面で受験日を変えられる。「まだ決めていない」にも戻せる。
- 「まだ決めていない」のときは、受験日までの日数（ホーム・タイトル画面）を出さない。
- 受験日を過ぎたら、ホームに「受験日を過ぎました。次の受験日を設定しますか」を出し、そこから設定できる。
- 保存データの設定に `examDate`（YYYY-MM-DD または null）と `examAsked`（聞いたか）を持つ。古い記録や、日付として読めない値は「まだ聞いていない」に戻す。すでに学習記録がある利用者にも、次に開いたとき1回だけ聞く。

**(2) 非公式であることの表示と免責**
- 「もっと」の中に「このアプリについて」の画面を置く。書くこと: ①非公式で、試験の実施団体とは関係がない ②合格を保証しない ③問題・解説はオリジナルで、誤りが含まれる可能性がある。誤りは「誤りを報告」から知らせてほしい ④公式の情報は公式サイトで確かめてほしい（`officialLinks`） ⑤音の素材の作者名（`docs/sources/audio-licenses.md`。CC0 で表示義務は無いが、作者名を出す。表の作者を全員載せることは `sound.test.js` が見る） ⑥権利について（2026-10-11 先生決定）：問題・解説・図・キャラクター・プログラムは Aisunia がこのアプリのために作ったもので、無断で転載・配布しないでほしいこと。キャラクター・ボス・バッジの絵は Aisunia が生成AI（ChatGPT）を使って作ったこと。「© 2026 Aisunia」。著作権の表示は法律上の義務ではない（著作権法17条2項）ので、意思表示として置く。AI で作ったことを書くのは、OpenAI の利用規約が人が作ったと偽ることを禁じているため（表示の義務ではない）。
- タイトル画面の下にも、小さく「非公式アプリ」と出す。
- 実施団体の正式な名前は、各試験の公式サイトで確かめてから書く（G検定: 一般社団法人日本ディープラーニング協会＝JDLA ／ DXビジネス検定: 一般社団法人 日本イノベーション融合学会＝IFSJ。2026-10-06 に先生が受けるのは学会の試験と確認。同じ名前の試験を株式会社ネクストエデュケーションシンクも実施しており、学会は「一切の関係がありません」としている。アプリの出題範囲は、学会のシラバス（申込フォームで入手）に合わせて組み直した。ネクストエデュケーションシンクのシラバス由来の章立ては使っていない）。
- 商標について「登録商標です」とは書かない（登録の状態は確かめていない）。書くのは「試験の名称は各実施団体のものです」まで。
- 団体名などは資格ごとに違うので、文言の土台は `config.json` の `about` に置く。

**(3) 学習記録の引き継ぎ（書き出しと読み込み）**
- 学習記録はブラウザの中（localStorage）にしか無く、機種変更や消去で消える。設定画面に「書き出す」「読み込む」を置く。
- 書き出し: JSON ファイル。ファイル名に資格の id と日付を入れる。中に、アプリの id・記録の版・学習記録と設定だけを入れる（個人を特定できる情報はもともと持っていない）。
- 読み込み: 別の資格のファイル・壊れたファイル・新しい版のアプリで作ったファイルは断る。受け入れた中身は既存の正規化（`mergeState`）を通す。上書きする前に「いまの記録は消えます」の確認を出す。
- Android の Chrome で動く作りにする（Blob のダウンロードと `input type=file`）。

**(4) 問題の誤りの報告**
- 問題の解説の画面と、用語カードの画面に「誤りを報告」を付ける。
- 押すと、報告の先を開く。報告の先は `config.json` の `reportUrl` で決める。開く先に、アプリ名・問題（カード）の ID・その文の冒頭を、あらかじめ入れて渡す（https は URL の `title` と `body`、mailto は `subject` と `body`）。
- 利用者がスクリーンショットを添えて「ここ」と示せるようにする（2026-10-04 先生の要望）。本文の最後に添付のお願いを入れ、ボタンの近くにも添付できる旨を出す。
- 報告の先は、問い合わせ専用のメールアドレス（屋号のドメイン `support@aisunia.com`。Google Workspace のメールエイリアス）にする（2026-10-04 先生決定。`reportUrl` は切り替え済み。2026-10-10 先生が「supportは届くよ」と届くことを確認した）。先生の個人のメールアドレスは使わない。差し替えは `reportUrl` の1行だけ。
- `reportUrl` が無い・https でも mailto でもないときは、ボタンを出さない。

**(5) 提供者の表示**（2026-10-04 先生了承）
- 「このアプリについて」の一番上に「提供：Aisunia」（屋号）とロゴ（`shared/images/aisunia-logo.webp`）を出す。

**(6) 文字の大きさを選べる**（2026-10-05 先生決定。長い問題文や、年配の受験者でも読みやすくするため）
- 設定画面に「文字の大きさ」を置く。選べるのは4段階: 小さめ（0.9倍）／ふつう（1.0倍）／大きめ（1.15倍）／とても大きい（1.3倍）。倍率は本文16pxに対する。初期は「ふつう」（これまでの大きさ）。
- 選んだら、その場でアプリ全体の文字が変わる（画面を開き直さない）。選ぶ欄のそばに見本の文（「この大きさで表示します。…」）を出し、変わったことが見て分かるようにする。
- 変わる範囲: 本文・問題文・選択肢・解説・用語カード・ボタン・下のメニューなど、アプリの文字すべて。変わらない範囲: 図（SVG）の中の文字。図は幅に合わせて全体が拡大・縮小される作りで、画面の幅いっぱい（最大360px）で出しているため、文字の大きさの設定では変えない。
- 大きくしても、画面の横にはみ出さない。ボタンや下のメニューが重ならない。押せる高さは48px以上のまま。幅360pxで「とても大きい」にしても崩れないこと。
- 保存データの設定に `textSize`（`small` / `normal` / `large` / `xlarge`）を持つ。古い記録（項目なし）や、ありえない値は「ふつう」に戻す。学習記録の書き出し・読み込みにも含める。
- 配色と同じく、タイトル画面から効かせる（端末の記録から先に読む）。
- 「小さめ」は本文が14.4pxになり、本文16px以上の原則（読みやすさ）を下回る。利用者が自分で選んだときだけの例外とし、初期値にはしない。

### 3-2-b. アプリの版の番号（2026-10-22 先生決定）

- **タイトル画面：** いちばん下に小さく薄い字で「Ver. 0.9.0」と出す（service worker の番号は出さない）。「タップしてはじめる」より目立たせない（2026-10-22 先生決定）。
- **出す場所：** 設定画面のいちばん下に「版 0.9.0（117）」の形で出す。前が人に見せる番号、括弧の中が service worker の番号（公開のたびに上げている番号。スマホが新しい中身を取り直す合図）。両方出すのは、先生が新しい版に切り替わったかを見分け、不具合がどの版で起きたかを言えるようにするため。
- **人に見せる番号の決まり（3つの数字）：** Semantic Versioning（https://semver.org/lang/ja/ ）の形を、このアプリ向けに読み替える。
  - 1つ目：試験の形・出題範囲が大きく変わって作り直したとき（シラバス改訂への作り直しなど）
  - 2つ目：新しい機能を足したとき（ボス戦・学習時間のグラフ・基礎のことばなど）
  - 3つ目：問題・説明・図・見た目の直しだけのとき
  - 上げたら、それより右の数字は0に戻す（1.3.5 の次に機能を足したら 1.4.0）
- **アプリごとに別の番号。** shared/ を変えたら、変わった中身に応じて4つとも上げる。
- **始まり：** 4つとも 0.9.0 から。ストアに出す日に 1.0.0 にする（正式版の前であることを 0 で表す）。
- **上げる人：** 公開の手順の中で、門番が前の公開からのコミットを見て、どの数字を上げるか決める。
- Google Play に出すとき申告する人に見せる番号（versionName）は、この番号にそろえる。画面の中に版を出すこと自体は、Android の公式の説明（https://developer.android.com/studio/publish/versioning ）では求められていない（デベロッパー ポリシーの本文までは確かめていない）。

### 3-3. 聞き流し（耳だけで学ぶ）は見送り（2026-10-07 先生決定）

- 先生の要望で、スマホの読み上げの声（Web Speech API）を使う試し作りを作って公開した（e19bedc）。実機では、画面を消すと読み上げが止まり、ロック画面に操作が出なかった。先生が欲しい「5秒戻す・進む」「つまみで好きな所へ移動」も、読み上げの声には時間の軸が無いので作れない。
- これらを満たすには、前もって音声ファイルを作る方式が要る。無料で規約にも容量にも収まる方法（VOICEVOX）はあるが、生成と読み間違いの手直しの手間が大きく、カードを直すたびに作り直しが要る。
- 先生の判断（逐語）「無料がいいが、利用規約や料金、データ容量的に難しい場合は、この実装は辞めよう。大変すぎる。」を受け、試し作りも外した（先生の選択 B）。調べた結果は試験の後に改めて考えるときの材料として、この節に残す。

### 3-4. あとで見る（2026-10-08 先生の要望）

先生の言葉（逐語）「あとで見返して、ゆっくり理解したい問題にチェックを入れ、まとめて見れる画面が欲しい。」

- 印を付ける所: 問題の画面（答える前から押せる。迷った問題に、答えが見える前に印を付けられる）と、解説の画面（答えたあと・模擬試験の結果の見直し）に「あとで見る」のボタンを置く。問題の画面では、選択肢の下に置くと選択肢の1つに見えるため、上の見出し（何問目かの行）の右端に、しおりの絵と文字で小さく置く（2026-10-08 先生の指摘）。押すごとにオン／オフが切り替わり、オンのときは色と文字（「あとで見る ✓」）で分かる。押せる高さは48px以上。模擬試験の解いている最中には出さない（試験の画面の決まりを変えない）。
- 見る所: 「もっと」の「あとで見る」（件数つき）と、「復習」の画面から入る。画面は #/later。印を付けた問題の一覧（章の名前・問題文の最初の部分・印を付けた日）を、印を付けた新しい順／章の順で並べ替えられる。1つ選ぶと、問題文・選択肢・正解・解説（図・覚え方・関連する用語カードを含む）を、解かずに読める。そこから印を外せる。0件のときは、どこで印を付けられるかを案内する。
- 解く: 一覧の「印を付けた問題だけを解く」で、その問題を出題する（1回に最大20問）。正解しても印は自動で外さない（外すのは本人）。
- 保存: 学習記録に `later`（問題ID → 印を付けた時刻のミリ秒）を持つ。古い記録（項目なし）は空。数でない値は捨てる。学習記録の書き出し・読み込みにも含める。G検定とDXビジネス検定は記録が別なので、それぞれ別に持つ。データから消えた問題のIDは、一覧にも件数にも出さない（記録には残す）。

### 3-5. 「どっち？」早押し（2026-10-09 先生決定）

先生の言葉（逐語）「A、B、Cを作ろう！」（A＝似た2つの語の早押し、B＝合格予想メーター、C＝章のボス戦。門番が出した案から選んだ）。

- ねらい: 似た手法・似た制度の取り違え（G検定・DX とも多く問われる）を、遊びながら見分けられるようにする。
- 出題: 用語カードの一行目（oneLine）を出し、そのカードの題名と、そのカードの「混同しやすい相手」（confusions）の題名の2つから選ぶ。2つの並びは毎回ランダム。問題は新しく作らず、カードから自動で作る（G検定は 456 組、DX は 214 組ある。2026-10-09 門番が数えた）。
- 答えを伏せる: 一行目の中にある題名の語は「〇〇」に置き換える。題名が「A・B」「AとB」「A／B」のように複数の語なら1語ずつ、括弧つきの別名（「ディープラーニング（深層学習）」）なら括弧の外と中の両方を伏せる。伏せたあとも題名の語が残る（伏せきれない）カードは出さない。
- 一行目に相手の題名がそのまま書いてある組は出さない（消去で答えが分かるため。2026-10-09 担当の実測で G検定 27・DX 7 組）。
- 進め方: 入口から、まず説明と記録のはじめの画面を出し、「はじめる」で始める（いきなり時間が走らないように）。1回20問。1問の秒数は、出す説明の長さで決める：選ぶ3秒＋読む時間（1秒に8字）を切り上げ（2026-10-19 先生決定 A。それまでは一律5秒で、先生「問題文が長すぎて5秒じゃ無理」。一行目の長さの真ん中は G検定 104字・DX 78字・AIパスポート 75字で、5秒では1秒に20字ほど要った）。時間切れは不正解。正解が続くとコンボの数が伸び、画面に出す。間違えた・時間切れのときは、2つの違い（confusions の point）を2秒ほど出してから次へ進む。
- 結果: 正解数・最高コンボ、間違えた組の一覧（2つの題名と違いの1行。タップで用語カードへ）。最高の正解数と最高コンボを記録し、更新したら知らせる。
- 結果発表の演出（2026-10-20 先生決定 A。先生の言葉（逐語）「どっち？早押しが最後までいったあとの結果発表がないのが残念」「演出が寂しかっただけ」。秒数チャレンジの結果には付けない）: 結果の画面に切り替わったら、次の順に出す。①「結果発表！」の文字が大きく出る ②正解数が 0 から約1.5秒で数え上がる（「15 / 20 正解（75%）」の 15 の部分。0問正解なら数え上げず 0 のまま） ③止まったところで、ランクがはんこのように押される ④あい先生が、ランクに合わせた一言をかける（吹き出しは模擬試験の結果と同じ部品・見た目。タップの遊びの対象外） ⑤正解数かコンボの記録を更新したときだけ、記録更新の文を出し、紙吹雪とジングル（お祝いの画面のバッジの効果音。新しい音のファイルは足さない）を出す ⑥その下に、最高コンボ・まちがえた組・「もう一度」「戻る」をいままでどおり並べる。効果音・振動は設定に従う（オフなら鳴らさない）。
  - ランク: S＝全問正解（出題数すべて）／A＝正解が80%以上／B＝55%以上／C＝それ未満。20問なら A＝16問以上、B＝11問以上、C＝10問以下（先生の指定と同じ）。出せる組が足りず出題数が20問に満たないときも、同じ割合で決める（例: 10問なら A＝8問以上、B＝6問以上）。出題数が0のときは C。判定は純粋な関数（`dochiRank`。百分率を掛け算で比べ、小数の誤差で境界が外れないようにする）。

## 5. 体系的に学べること（このアプリの芯）

1. **シラバスを地図にする。** 大項目 → 中項目 → 小項目の木を「ステージ」として表示し、項目ごとの正答率・習熟度を色で見せる
2. **用語カード（概念カード）。** シラバスの小項目ごとに「一言で言うと／背景とポイント（生まれた背景・解く問題・名前の由来・押さえどころ。データの why 欄）／つながる用語／よくある混同」をまとめたカードを置く。問題を解く前後に読める
3. **解説は4点セット。** ①正解の理由 ②各誤答がなぜ違うか（「適切でないもの」を選ぶ問題では、ほかの選択肢は正しい文なので、画面の見出しを『ほかの選択肢がなぜ答えにならないか』にする。2026-10-08 先生決定） ③覚え方（語呂・対比表・因果のつながり） ④関連する用語カードへのリンク
4. **間違えた問題からの学び直し。** 間違えると、その問題の用語カードと「混同しやすい相手」を見せる。復習は間隔をあけて再出題（翌日・3日後・7日後。2026-10-23 に14日後をやめた。§6-3）
5. **つながりで覚える。** 例：「勾配消失 → 原因はシグモイドの微分が小さいこと → ReLU で緩和 → さらにスキップ結合」のように、カード間を因果でたどれる
6. **苦手を見つけて、すぐ解き直す。** 小項目ごとの正答率から、苦手な所・まだ手を付けていない所・得意な所を見せ、苦手はボタン1つでその範囲の出題を始められる（詳しくは「6. ゲームの要素」の「苦手の分析」）

### 6-2. 学習時間の振り返り（2026-10-17 先生要望）

先生の要望：「日々の勉強時間の総数は出るけど、日単位でも集計して振り返るようにはできないか？」「日ごと週ごと月ごとも切り替えられるようにしたいな。年ごとも。期間も指定できたらうれしい。」

- **日ごとの記録：** 学習記録の `studyDays`（'YYYY-MM-DD' → その日の秒数）。学習時間を足すとき、合計（`studySeconds`）と一緒に、その日（端末の日付。連続日数・1日の目標と同じ区切り）の分にも足す。**古い日は消さない**（1日分は30〜50文字ほどなので、何年ためても収まる）。1日の上限は24時間（86400秒）。過去の分は日ごとに分けられないので、**この機能を入れた日から**ためる（過去の値を推定して足さない）。ホームの総学習時間は、それ以前の分も含んだ合計のまま。
- **`state.daily`（答えた数・正解数）に秒数を入れない理由：** `daily` に『記録がある日』は、連続日数・1日の目標・合格予想の判定に使っている。秒数だけの日（画面を開いただけで1問も答えていない日）を `daily` に作ると、その判定の意味が変わる。だから学習時間の日ごとは別の項目にする。
- **持ち方：** `studySeconds` と同じ扱い。科目のあるアプリでは科目をまたぐ共通の記録に入れる。書き出し・読み込みに含める。項目の無い古い保存データ・ファイルは空として読む。日付でないキー・数でない値・負の値は捨てる。
- **画面：** ホームの『総学習時間』を押すと開く（`#/study`。「ホーム」の中の画面）。**日／週／月／年**を切り替えて、棒グラフ（縦軸は時間）と、合計・1日あたりの平均・勉強した日数・答えた問題数を出す。**期間（開始日〜終了日）**も指定できる。初めは『日ごと・ここ30日』。切り替えると、その単位の初めの期間（週＝ここ12週、月＝ここ12か月、年＝ここ5年）に戻る。週の始まりは月曜。**記録の無い日も0として棒を出す。** 期間の端の日は含める。期間が週・月・年の途中から始まる・途中で終わるときは、その週・月・年のうち期間に入る日だけを数える（棒の合計と期間の合計が合う）。ただし終わりが今日の棒（今週・今月・今年）は、先の日がまだ来ていないだけなので『期間の一部』とは言わない。終了日が今日より先なら今日にそろえる。開始日が終了日より後なら入れ替える。期間は最長10年。
- **平均：** 『記録のはじまりの日』と『期間の開始日』の遅いほうから終了日までの日数で割る（この機能を入れる前の日を0日として平均を薄めない）。記録がまだ無いときは平均を出さない。
- **棒が多いとき：** 棒の幅は単位ごとの最小の幅（日＝14px。週40・月48・年56）を下回らせず、足りない分は横にスクロールさせる（開いたときは新しい側＝右端）。日ごとで90日を超えたら『週ごとに切り替えると見やすい』と添えて、ボタンで週ごとに切り替えられる。
- **数値（2026-10-17 先生要望「グラフの上に数値も出して、正確な数字も把握できるように」）：** 各棒の上に短い数値を出す。1分未満は『<1分』、100時間までは『0:45』『1:05』（時間:分。1時間未満も『0:38』の形にそろえる。2026-10-18 先生「38分は『0:38』と表記すればいいのでは？」。『38分』と『2:39』が並ぶと単位が混ざって読みにくい）、それ以上は『120時間』。0の日は出さない（0分の棒は薄い細線だけ）。『1:05』は狭い幅で読める最短の書き方（『1時間5分』だと棒の幅に収まらない）。数値は**いつも横書き1行**（2026-10-17 先生要望「1行で『37分』としたい」。縦向きは読みにくかった）。棒の幅より長くてよく、隣の棒の上にはみ出してよい。**隣の数値と重なるときは1段上げて両方出す**（2026-10-18 先生「タップしないと表示されないのね」。隣り合う同じくらいの高さの棒で、片方が隠れていた）：選んでいる棒、それから右（新しい日）から順に、まず棒の真上・真ん中に置き、すでに置いた数値（左右 4px・上下 1px のすき間）やほかの棒と重なるなら、左に寄せる（自分の棒の右端にそろえる）・右に寄せる（左端にそろえる）・1段（文字の高さ＋2px）上げる、を順に試す（同じ日の2回目の指摘「前日のが出てこない」。細い棒では数値が棒より長く、背の高い隣の棒にかかって隠れていた）。どれでも重なる・上の余白や左右の余白（14px）を超えるときだけ隠す（2段上げると、どの棒の数値か分かりにくい）。右の余白は、いちばん右（今日）の数値を自分の棒の左端から右へ伸ばして置けるだけ広げる（最低16px。`barRightPadPx`。2026-10-19 先生「何故か今日の時間が出てないな」。文字を大きくすると、今日の数値が背の高い前日の棒と右端に挟まれて隠れていた）。計算は `placeBarValues`（幅は文字の大きさの設定に合わせて見積もる）。隠れた数値は、その棒を押すと下の詳細の文で読める（背の高い棒の隣の低い棒は、押しても棒の上には出ず、詳細の文で読む）。数値は棒の上の専用の余白（44px）に出し、縦軸の上端は棒の最大の高さ。正確な値は、棒の読み上げ・押したときの詳細の文（『1時間5分』『45秒』の形）にもある。数値は切り捨て（詳細の文と同じ向き）。
- **切り替えの動き（同じく先生要望「パッパッと切り替わらず、元のグラフから新しいグラフにグーンと変わって」）：** 単位・期間を切り替えても、グラフの入れ物は作り直さない。右端（今）の棒をそろえて引き継ぎ、棒の高さを約0.4秒でなめらかに伸び縮みさせる。本数が増えるときは、増えた棒が左で0から伸びながら幅が広がり、減るときは、左の棒が0へ縮みながら幅が0になって消える。棒の上の数値と縦軸の目盛りは、元の値から新しい値へ数え上がり・数え下がる。『視差効果を減らす』（prefers-reduced-motion）の端末では、すべてすぐ切り替わる（CSS の一括停止＋画面側の判定）。
- **選んだ棒の見え方：** 選んだ棒は、棒そのものに縁を付ける（枠をグラフの上まで伸ばさない。棒と見分けにくくなるため）。横にスクロールして左が切れているときは、左の端をぼかして『続きがある』と分かるようにする。名前（日付）は、右端（今）から数えて何本かおきに出し、いちばん新しい棒の名前がいつも見える。
- **読み上げ・押す：** 棒は1本ずつボタンで、読み上げには『10月3日(金) 1時間5分、答えた問題 12問』の形で数字を出す。押す（タップ）と、グラフの下にその棒の数字を出す。棒の色は色の変数で、暗い配色でも読める。
- **計算の置き場：** 集計（日・週・月・年の区切り、期間の整え方、平均）は `shared/js/lib/studyreport.js` の純粋な関数にして、テストする（月末・年またぎ・うるう年・週が月や年をまたぐ境目・期間の端・記録が無い期間・壊れた保存データ）。画面は `shared/js/views/studyreport.js`。

### 6-3. 復習の量を抑える（2026-10-23 先生決定）

先生の言葉（逐語）「ここ数日、復習問題が250問前後になっててうんざりしてる。。。」「その60問は、苦手な問題を優先して入れてほしい。苦手を克服するのが点数源のはずだから。」

- **間隔を3回にする：** 間違えた問題は翌日・3日後・7日後に戻ってくる。3回続けて正解したら卒業（これまでの14日後の4回目はやめる）。途中で間違えたら翌日からやり直し（これまでどおり）。これまでの記録で14日後を待っている問題は、すでに3回正解しているので卒業として扱う（記録は消さない）。
- **受験日より後の復習は入れない：** 受験日を設定していて、次の復習の日が受験日より後になるなら、その問題は卒業にする（本番の前に役に立たないため）。受験日を過ぎた後・受験日が未設定のときは、ふつうの間隔。
- **1日の上限は60問：** 期日が来ている問題が60問より多いとき、「今日の復習」はそのうち60問だけにする。あふれた問題は消さず、期日が来たまま残り、次の日にまた選ぶ候補になる。
- **苦手な問題から選ぶ：** 60問は、次の順で選ぶ。①問題ごとの正答率（正解した回数÷解いた回数）の低い順 ②間違えた回数の多い順 ③期日の古い順。苦手の克服が点数になるため。
- **見せ方：** ホームと復習の画面の件数は、上限を当てた数（最大60問）。あふれがあるときは「ほかに◯問が待っています（苦手な問題から出しています）」と小さく添える。60問を終えた日は、続けたい人のために「もっと復習する」で残りを同じ順で出せる（1日の上限は、出す数の目安であって、解ける数の上限ではない）。
- **ほかへの影響：** ボス戦・「あとで見る」・苦手な分野の分析・XP は変えない。4アプリ共通（shared/）。

## 7. 問題データの形（両資格共通）

`<資格>/data/` に置く。JSON。

```json
{
  "id": "G-DL-ACT-001",
  "syllabus": ["技術分野", "ディープラーニングの概要", "活性化関数"],
  "format": "single",
  "difficulty": 2,
  "stem": "問題文",
  "choices": ["A", "B", "C", "D"],
  "answer": 1,
  "explanation": "正解の理由",
  "whyWrong": ["Aが違う理由", null, "Cが違う理由", "Dが違う理由"],
  "memoryTip": "覚え方",
  "concepts": ["CONCEPT-ID"],
  "sources": [{ "title": "出典名", "url": "https://..." }],
  "status": "verified"
}
```

- `format`: `single`（1つ選ぶ）／`not`（適切でないものを選ぶ）／`fill`（空欄補充）／`scenario`（場面を読んで判断。DX向け）／`combo`（問題文の空欄（ア）（イ）（ウ）に入る語の組み合わせを選ぶ。選択肢は「（ア）〇〇　（イ）△△」の形。選択肢を並べ替えても崩れない。2026-10-09 追加。市販の模擬試験で12%あり、アプリでは約2%で、数えて割合をそろえるため）
- `qtype`（DX は必須。G検定は持たない）: 出題の型。`term`（用語理解）／`relation`（関係理解）／`causal`（因果連鎖）／`loop`（循環構造）／`tradeoff`（トレードオフ）／`interdep`（相互依存）／`miscon`（誤構造検出）のどれか。`format`（答え方の形）とは別の軸で、問題が何を問うかを表す。決まりは §7-4
- `answer` は0始まりの添字。`whyWrong` の正解位置は `null`
- 任意の欄 `figures`: 図の ID の配列（例 `["fig-g-activation"]`）。問題にも用語カードにも置ける。決まりは §7-2
- 任意の欄 `stemPlain`: 問題文を、専門用語を使わずに言い直した文字列。無ければ欄ごと省く。決まりは §7-3
- 任意の欄 `negative`: `true` のとき、`format` が `not` でなくても「適切でないものを選ぶ」問題として扱う（札『適切でないものを選ぶ』を出し、解説の見出しを『ほかの選択肢がなぜ答えにならないか』にする）。`scenario` の問題で適切でないものを選ばせるときに付ける（`format` は1つしか持てないため）。2026-10-18、先生の指摘「適切でないもののラベルはつけなくていい？」で、DX の場面問題26問に札が出ていなかったため追加。検査は、問題文に「適切でない」「不適切」「誤っている」があるのに `format` が `not` でも `negative` でもなければ NG
- 用語カードは `concepts.json` に `{ id, syllabus, title, oneLine, why, links:[{id, relation}], confusions:[{id, point}], sources, status }`
- シラバスの木は `syllabus.json`（DX の形は §7-4）
- 資格ごとの設定（名前・受験日・模試の問題数と時間・配色）は `<資格>/config.json`

### 7-2. 図（SVG）の決まり

文字だけでは分かりにくい用語・問題の解説に、図を添える。計画と図ごとの根拠は `docs/sources/figure-plan.md`。

**データ**

- 用語カードにも問題にも、任意の欄 `figures`（図の ID の配列。無ければ図なし）を置ける。例: `"figures": ["fig-g-activation"]`
- 図の ID は `fig-` で始まる小文字の英数字とハイフン（例 `fig-g-confusion-matrix`）。資格の印を入れる（G検定は `fig-g-`、DX は `fig-dx-`）
- 図の本体は `<資格>/data/figures/<図のID>.svg` に置く。1枚の図を複数のカード・問題から使い回す。G検定と DX で似た図があっても、資格ごとに別の ID で置く
- 用語カードの画面（用語の説明の下）と、問題を解いた後の解説（「正解の理由」の下）の両方に出す。用語カードが図を持っていても、問題の `figures` が空なら問題の解説には出さない（問題ごとに、答えの理由が分かりやすくなる図だけを指定する）

**描き方**

| | 決まり |
|---|---|
| 作り手 | SVG をこちらで手書きする。**中身もオリジナル**（教科書・論文の図をなぞらない）。外から来た文字列は混ぜない |
| 数値・式・関係 | そのカードの `sources` の一次情報で確かめたものだけを描く。**確かめられなかった数値は描かない**。取得は curl（PDF は pdftotext）で全文を取って検索する |
| 例の数値 | 図の例（混同行列の件数、面積図の割合など）は、そのカードに紐づく問題の答え・選択肢に出る数値と同じにしない（解説で答えを先に見せない）。計算は自分でも確かめ直す |
| 大きさ | `viewBox` は幅 360 以下（標準は幅 320）。スマホの縦画面（幅360〜390px）で拡大せずに読めるよう、図の中の文字は画面上で 12px 相当以上（幅320の図では13）。横に長い図は避け、縦に積む |
| 配色 | 色は SVG に直書きせず、共通 CSS（`shared/css/app.css` の「図」の節）のクラスで付ける。クラスは既存の CSS 変数（`--text` `--accent` `--ok` `--ng` `--warn` など）を使うので、明るい配色・暗い配色の両方で見える。**色だけで区別させない**（線の種類・ラベルも併せて付ける） |
| 読み上げ | ルートの `<svg>` に `role="img"`、`<title>`（図の題）と `<desc>`（図が言っていること）を付け、`aria-labelledby` で結ぶ。題は画面にも見出しとして出る |
| 取り込み方 | 外部の画像として読まない（CSS 変数が効かない）。アプリが SVG の文字を取り、安全を確かめて画面に取り込む。取り込めない・読めないときは「図を読み込めませんでした」と出し、解説の文字は通常どおり出す |
| 禁止 | `<script>`・`<foreignObject>`・`<style>`・`style=`・イベント属性（`onclick` など）・`#` で始まらない `href`・外部への参照（`http` など）・`<image>` |
| オフライン | サービスワーカーがインストール時に、データが指す図をすべて取って保存する |

**検査**（`tools/check-data.js`、DX は `tools/check-data-dx.js` も同じ検査を持つ）

- `figures` が文字列の配列で、各 ID が形式どおりで、対応する SVG が `data/figures/` に実在すること
- `data/figures/` の SVG すべてについて、上の禁止事項が無いこと・`viewBox` が幅 360 以下であること・`role="img"` と `<title>`・`<desc>` があること
- どのカード・問題からも使われない SVG は警告（NG にはしない）

見ていないもの: 図の中身の正しさ（数値・式が出典と合うか）・文字の大きさと見た目（画面で目視する）。

### 7-3. 問題文の意味（2026-10-06 利用者の要望）

**要望（逐語）:** 「問題文自体が用語だらけで、理解すら難しい問題が時々ある。そもそも問題文はどういう意味なのか？を解説してほしい。」

**経緯:** 2026-10-06 に問題文の下のボタンとして作ったが、同日、利用者の指示（逐語：「問題文の意味は、問題文にボタンにつけるのではなく、回答後に解説や用語の説明があるでしょ？そこに入れたい。」）で、**回答後の解説に移した**。問題を解く前には出さない（ボタンも置かない）。

**何を出すか:** 問題のデータの任意の欄 `stemPlain`（問題文を、専門用語を使わずに言い直した文）があるとき、回答後の解説（`shared/js/views/explain.js` の `explanation`）の**先頭**（間違えたときに出る『まず用語を確認しよう』よりも前）に、見出し『問題文の意味』の欄を出す。順番は『問題文の意味 → まず用語を確認しよう（間違えたとき）→ 1 正解の理由 → …』。中身は `stemPlain` の文そのまま。`stemPlain` が無い問題には欄を出さない（空の欄を置かない）。

**なぜ先頭か:** 用語の確認も解説の4点（正解の理由・誤答・覚え方・関連用語）も、問題文の意味が分かっている前提で読むものだから。問題文の言い直しを先に読ませ、そのあとで用語と『なぜその答えか』を読ませる（2026-10-06 先生の指示：『問題の意味が分かってから用語を見る順のほうが自然』）。

**出す画面:** 解説を出す所すべて。①出題画面（ステージ・復習・秒数チャレンジ）で答えたあと ②結果画面の『まちがえた問題』の一覧 ③模擬試験を終えたあとの見直し。どれも解いたあとなので、本番と同じ条件で受ける模擬試験の最中には影響しない。

**用語の説明は足さない:** 問題文に出てくる用語の説明は、すでに解説にある『まず用語を確認しよう』（間違えたとき）と『関連する用語カード』が担う。同じことを二重に出さないため、問題文から用語を拾って出す仕組みは持たない（初版で作った `stemhelp` は撤去した）。

**採点・記録との関係:** 表示するだけ。XP・正答率・連続正解・復習の間隔に影響しない。

**画面の決まり:** 解説の他の欄と同じ枠（`ex-block`）。文字は rem なので、文字の大きさの設定（小さめ〜とても大きい）で一緒に伸び縮みする。色は共通の変数だけで、明るい・暗いの両配色で読める。幅320〜390pxで横にはみ出さない（長い語は折り返す）。

**検査（`tools/check-data.js`・`tools/check-data-dx.js`）:** `stemPlain` がある問題について、①空でない文字列であること ②前後に空白・改行が無いこと ③**200文字以内**（問題文の言い直しで、長い解説にしない） ④問題文と同じ文でないこと（NFKC・空白を除いて比べる）。欄が無い問題は、そのまま通す（任意）。**初版にあった『選択肢の文をそのまま含んだら NG』は外した**：答える前に見える場所ではなくなり、答えのヒントを避ける必要が無くなったため（正解は解説の別の欄で明示している）。

見ていないもの: `stemPlain` の中身が、問題文の正しい言い直しになっているか・専門用語を使っていないか（人が読んで確かめる）。

### 7-4. DXビジネス検定の章立てと出題の型（2026-10-06 先生決定）

日本イノベーション融合学会（IFSJ）の DXBz シラバス（2026年8月4日版）に合わせて作り直した。シラバスは申込フォームで入手した非公開の資料なので、**再配布しない**。

**木（`dx-biz/data/syllabus.json`）:** 3段。領域 ＞ 分類（＝章・ステージ）＞ 知識区分。

| 段 | 中身 | id の形 |
|---|---|---|
| 領域 | 補足でない4つ（コアDXBzイノベーション領域／DX戦略イノベーション領域／DX技術イノベーション領域／社会実装イノベーション領域）＋補足1つ | 英大文字（`CORE` など） |
| 分類 | 補足でない領域の下に3つずつ、計12（A〜L）。章番号は概要の三角図の順（コア→戦略→技術→社会実装）: 01=A 02=B 03=G 04=C 05=D 06=E 07=H 08=I 09=J 10=F 11=K 12=L。補足の領域の下は 13 の1つ | 章番号2桁＋記号（`01A`、補足は `13S`） |
| 知識区分 | 補足でない分類の下は、ちょうど「基本概念／応用事例／最新事例＆トレンド」の3つ（この順）。補足の下は、旧章の主題（DXの前提知識・マーケティング・経済性・消費・産業構造・戦略モデル・オペレーションと顧客関係・収益モデル・DX事例の共通構造） | 分類の id＋`-`＋番号 |

- **入れるのは領域・分類・知識区分の名前まで。** 知識項目（代表的な用語例）の一覧は入れない（`keywords` は持たないか、空）。最新事例の見出し（社名・金額入り）は、カードの題名にも写さず一般化する。
- **補足の印:** 補足の領域だけに `"supplement": true` を付ける（値は true だけ。分類・知識区分には付けない）。補足は、シラバスの例に無いが学ぶ価値のある一般的なビジネス概念と DX の前提知識（DXレポート・DX推進ガイドライン・デジタルスキル標準など）。章の練習では解けるが、**模擬試験には出さない**（§6 の模擬試験）。
- **外したもの:** 旧ケース章（09〜12）の企業カード19枚とその問題、NET 固有の語（トキ消費・イミ商材・ジオメディア・グルーポンモデル・ウィンドウイング）のカードとその問題。アプリは読まないが、`dx-biz/data/removed/` に残す（`index.json` には載せない）。学習記録に残った外した問題の ID は、データに無いので出題・地図の習熟・苦手の分析には使われない（`shared/js/lib/progress.js` の `dueQuestions` も、データに無い ID を落とす）。復習画面の『復習の予定』の件数（`srs.js` の `upcoming`）も、データに無い問題 ID は数えない（2026-10-06 に対応）。旧章立てのステージの星（`stages` の記録）は、章の名前が変わったので新しい章には引き継がれない。旧ケース章の「共通構造」のカード4枚は補足に残す。

**ファイル:** 1章＝1ファイル。`questions/NN_<名前>.json`・`concepts/NN_<名前>.json`（NN は章番号）。問題・カードの `syllabus` は3段で、ファイルの章番号＝分類の章番号。

**出題の型 `qtype`:** 学会の概要が示す7つの出題類型。定義の文は写さず、ここでは自分の言葉で書く。

### 7-5. 基礎のことば（2026-10-17 先生決定）

**要望（逐語）:** 「次元とか、パラメータとか、こういった基本的な言葉がわかってないかも。基礎の解説ってあるのかな？」

**経緯:** カードは試験範囲（シラバス）の項目ごとに作ってあり、次元・パラメータ・ベクトル・線形・特徴量・ラベルのような、カードや解説を読むための土台の言葉のカードが無かった。先生の決定（逐語）：『1.B』『2.同じものを作る。』。つまり ①土台の言葉のカードを作り、さらにカードや解説の文にその言葉が出てきたら、その場で開けるようにする ②G検定とDXの両方に作る（生成AIパスポートも同じ仕組みで足せる）。

**目的:** 用語カードの文や問題の解説で、読み手が知らないかもしれない土台の言葉（試験には出ないが、読むために要る言葉）の意味を、画面を離れずに確かめられるようにする。

**試験範囲との関係（入れないもの）:** 基礎のことばは試験範囲の外。**地図・ステージ・問題・模擬試験・進み具合（カードを見た数など）・バッジ・どっち？・ボス戦の出題には入れない。** 記録（`state`）にも何も保存しない。`app.data.basics`（語の一覧）と `app.data.basicsMatcher`（文中で見つける道具）だけが持つ。

**データの形（`<資格>/data/basics.json`。無い・空・壊れているアプリでも壊れない）**

```json
[
  { "id": "B-001", "term": "次元", "aliases": ["次元数"], "oneLine": "一言の定義", "why": "身近な例を使った説明", "figures": ["fig-g-basic-dimension"], "notIn": [], "related": ["C-03-027"] }
]
```

| 欄 | 決まり |
|---|---|
| `id` | 必須。G検定 `B-NNN`・DX `DB-NNN`・生成AIパスポート `B-AP-NNN`（`tools/check-data*.js` が形を見る）。重複しない |
| `term` | 必須。文中で見つける語 |
| `aliases` | 任意。文中で見つける、ほかの呼び方（同じ語として数える）。`term` と同じもの・重複は読み込みで落とす |
| `oneLine` | 一言の定義（80字以内を目安。超えたら検査が WARN） |
| `why` | 身近な例を使った説明（数文） |
| `figures` | 任意。`data/figures/` の SVG の ID。決まりは §7-2 と同じ |
| `notIn` | 任意。**語を含むが別の言葉になる複合語の一覧**（例: `フィルタ` に対し `スパムフィルタ`・`協調フィルタリング`・`フィルターバブル`）。文中でこの複合語が出てきたら、その中の語には印を付けない。試験範囲のカードの title と同じ『付けない語』として照合に入れる（長い語が勝つ）。語を含まない・語そのものを書くと検査が WARN |
| `related` | 任意。つながる試験範囲のカードの ID。実在しなければ検査が NG |

ファイル名は既定で `basics.json`。`index.json` の `basics` で変えてもよい（`bosses` と同じ）。読み込みは `bosses.json` と同じ位置づけで、**読み込みの進み具合には数えない**（`app.js` の `loadExtras`）。実装は `shared/js/lib/basics.js`（DOM を使わない）。

**画面**

- **入口:** 用語カードの画面（`#/cards`）の先頭に、『基礎のことば（N語）』の1行を置く。語が0のアプリには出さない。
- **一覧（`#/basics`）:** 語と一言を並べ、検索できる（語・別の呼び方・一言を対象）。語が0なら『準備中』。
- **1語（`#/basic/<id>`）:** 用語カードと同じ形 ── 見出し（語）・ほかの呼び方・一言・図・『くわしく』（`why`）・『つながる試験範囲のカード』（`related`。押すとそのカードへ）。一言と `why` の中の、ほかの基礎のことばにも印が付く（自分の語には付けない）。
- **窓（文中の印を押したとき）:** 下から出るシート（用語カードを問題の途中で開くシートと同じ部品 `openSheet`）。語・一言・説明を出す。図かつながりがあれば『図とつながりも見る』で、同じ窓の中で1語の全体（図・つながるカード）に切り替える。『基礎のことばのカードを開く』で `#/basic/<id>` へ移る。**問題を解いている途中の画面（`#/play` `#/exam` `#/dochi` `#/boss`）では、この移動の道を出さない**（解いている問題が消えるため）。窓の上に窓（基礎のことば → つながるカード）が開くことがあるので、Esc は一番上の窓だけ閉じる。窓には『基礎のことば：（語）』の名前を付けて読み上げる。

**文中の印（リンク）の決まり**

| | 決まり |
|---|---|
| どこに付けるか | カードの一言・『背景とポイント』・『よくある混同』の違い／問題の解説の『正解の理由』・『誤答がなぜ違うか』・『覚え方』・『まず用語を確認しよう』のカードの一言と混同の違い／基礎のことば自身の一言と説明。実装は `shared/js/views/richtext.js` の `richEl`（問題の画面・結果の見直し・模擬試験の見直し・あとで見る・ボス戦の見直しは、どれも同じ `explanation` を通る） |
| 付けない所 | 問題文・選択肢・『正解: A. …』の見出し・『問題文の意味』（`stemPlain`。専門用語を使わない言い直しで、§7-3 のとおり用語の説明は足さない）・カードの一覧や検索の行（ボタンの中にボタンを入れ子にしない）・どっち？の伏せた一言・用語の丸ボタン（『まず用語を確認しよう』のカードへ飛ぶボタン。丸ボタンの中の文字には印を付けない） |

| 部品 | `<button type="button" class="basic-term" data-basic="<id>" aria-haspopup="dialog">`。読み上げでは『（語）、ボタン』と読まれ、キーボードで押せる。文字は必ず文字として入れる（HTML として解釈しない） |
| 1塊に1回 | **区画（見出しひとつの下のまとまり）で、同じ語に印を付けるのは最初の1回だけ。** 別名は同じ語として数える（`次元数` のあとの `次元` には付けない）。区画は、カードの『一言＋背景とポイント』（続けて読む）・『よくある混同』・解説の『正解の理由』・『誤答がなぜ違うか』全体・『覚え方』・『まず用語を確認しよう』全体・基礎のことばの『一言＋くわしく』。区画が違えば、また最初の1回が付く |
| 長い語を優先 | 重なる候補のうち長いものを先に取る。取った範囲と重なるものは捨てる（『次元削減』があれば、その中の『次元』は拾わない） |
| 試験範囲のカードの title との関係 | **カードの title（と、括弧の前・括弧の中。『次元削減（PCA）』なら『次元削減』と『PCA』）は『基礎のことばを付けない語』として照合に入れる。** **基礎のことばの語（`term`・`aliases`）が、カードの title の形とちょうど同じ文字列のときは、基礎のことばが勝つ（印を付ける。2026-10-18 変更。検査の WARN は出さない）。** カードの title のうち基礎のことばの語より長いもの（『Mask R-CNN』『Vision Transformer』『双方向 RNN』）は、今までどおり『付けない語』として長い語が勝ち、その中の『CNN』『Transformer』『RNN』には印が付かない。`notIn` と同じ文字列なら `notIn` が勝つ（今までどおり）。基礎のことばのほうが長ければ、そちらに印が付く。**カードの画面では、そのカード自身の title の形と同じ基礎のことばには印を付けない**（『畳み込みニューラルネットワーク (CNN)』のカードを開いているのに、本文の『CNN』に印が付いて同じ説明の窓が開くのは無駄なため。そのカードの区画を『印を付けた』状態で始めて実現する）。問題の解説などほかの画面は区別しない。**変えた理由（先生の言葉・逐語・2026-10-18）:** 「CNNも毎回『なんだっけ？』ってひっかかる」。CNN・RNN・Transformer を基礎のことばに足したが、3語ともカードの title の形と同じで、決まりのままでは1か所も印が付かなかった |
| 英字の語 | 語の最初・最後の文字が英数字なら、その前・後ろの文字が英数字のとき見つけない（`API` は `RAPID` の中では見つけず、`APIs` も見つけない。`このAPIは` や `REST-API` は見つける） |
