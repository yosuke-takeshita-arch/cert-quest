# cert-quest 要件定義書

作成: 2026-10-02

## 1. 目的

会社で取得する2資格（G検定・DXビジネス検定）を、Android スマホで遊びながら**体系的に**学べるようにする。
Web の一問一答は知識が断片的になるため、**解説・誤答からの覚え方・用語のつながり**を厚くする。

## 2. 対象の資格と期限

| 資格 | 受験日（最短） | 申込締切 | 本番の形式 | 出典 |
|---|---|---|---|---|
| G検定 | 2026-11-06(金) / 11-07(土) | 2026-10-29 | 多肢選択・145問程度・100分（オンライン） | https://www.jdla.org/certificate/general/ |
| DXビジネス検定 | 2026-11-29(日)（個人） | 公式ページ内で記載が食い違い。要確認 | 多肢選択・96問・60分。合否なし、スコア600/700/800でレベル認定 | https://www.nextet.net/kentei/dxbiz/ |

→ **G検定を先に作る。** DXビジネス検定は G検定の仕組みを使い回して後から作る。

## 3. 配布の形

- **PWA**（Web 技術で作り、Android の Chrome から「インストール」してホーム画面に置く。オフラインで動く）
- 資格ごとに**別アプリ**（アイコン2つ）。`g-kentei/` と `dx-biz/` がそれぞれ1つの PWA、共通部分は `shared/`
- 置き場所は GitHub Pages（2026-10-02 先生了承。URL を知る人は誰でも開けるため、会社の情報は入れない）
- 将来 APK に包み直せるよう、ビルド不要の素の HTML/CSS/JS で作る（フレームワーク・npm 依存なし）
- 学習記録は端末内（localStorage）。サーバーは持たない
- 全アプリが github.io の同じオリジンにあるため、Android の Chrome のメニュー「ホーム画面に追加」では2つ目以降を入れられない（同じオリジンにアプリが1つでもあれば「インストール済み」と判定される）。2つ目以降はホームの「アプリとしてインストール」ボタン（ページ側の案内）から入れる。manifest の id はアプリごとに重ならない値にする（2026-10-03）
- 画面の配色は設定で「明るい／暗い／スマホに合わせる」を選べる。初期は「明るい」（2026-10-03 先生決定）

### 3-2. 一般に配るために要る4つの機能（2026-10-04 先生決定）

**(1) 受験日を利用者が決める**
- 受験する回は人によって違う。受験日は `config.json` の `examDate` に固定せず、利用者が自分で決める（`config.json` の `examDate` は、聞くときの日付の初期値＝次の試験日の目安として使う）。
- 初回: タイトル画面の「タップしてはじめる」のあと、受験日がまだ決まっていなければ「受験日はいつですか」を聞く。日付を選ぶか「まだ決めていない」を選ぶ。あとで設定で変えられると一言添える。
- 設定画面で受験日を変えられる。「まだ決めていない」にも戻せる。
- 「まだ決めていない」のときは、受験日までの日数（ホーム・タイトル画面）を出さない。
- 受験日を過ぎたら、ホームに「受験日を過ぎました。次の受験日を設定しますか」を出し、そこから設定できる。
- 保存データの設定に `examDate`（YYYY-MM-DD または null）と `examAsked`（聞いたか）を持つ。古い記録や、日付として読めない値は「まだ聞いていない」に戻す。すでに学習記録がある利用者にも、次に開いたとき1回だけ聞く。

**(2) 非公式であることの表示と免責**
- 「もっと」の中に「このアプリについて」の画面を置く。書くこと: ①非公式で、試験の実施団体とは関係がない ②合格を保証しない ③問題・解説はオリジナルで、誤りが含まれる可能性がある。誤りは「誤りを報告」から知らせてほしい ④公式の情報は公式サイトで確かめてほしい（`officialLinks`） ⑤音の素材の作者名（`docs/sources/audio-licenses.md`。CC0 で表示義務は無いが、作者名を出す）。
- タイトル画面の下にも、小さく「非公式アプリ」と出す。
- 実施団体の正式な名前は、各試験の公式サイトで確かめてから書く（G検定: 一般社団法人日本ディープラーニング協会＝JDLA ／ DXビジネス検定: 株式会社ネクストエデュケーションシンクの NET検定シリーズ。2026-10-04 に公式サイトを取得して確認）。
- 商標について「登録商標です」とは書かない（登録の状態は確かめていない）。書くのは「試験の名称は各実施団体のものです」まで。
- 団体名などは資格ごとに違うので、文言の土台は `config.json` の `about` に置く。

**(3) 学習記録の引き継ぎ（書き出しと読み込み）**
- 学習記録はブラウザの中（localStorage）にしか無く、機種変更や消去で消える。設定画面に「書き出す」「読み込む」を置く。
- 書き出し: JSON ファイル。ファイル名に資格の id と日付を入れる。中に、アプリの id・記録の版・学習記録と設定だけを入れる（個人を特定できる情報はもともと持っていない）。
- 読み込み: 別の資格のファイル・壊れたファイル・新しい版のアプリで作ったファイルは断る。受け入れた中身は既存の正規化（`mergeState`）を通す。上書きする前に「いまの記録は消えます」の確認を出す。
- Android の Chrome で動く作りにする（Blob のダウンロードと `input type=file`）。

**(4) 問題の誤りの報告**
- 問題の解説の画面と、用語カードの画面に「誤りを報告」を付ける。
- 押すと、報告の先を開く。報告の先は `config.json` の `reportUrl` で決める。開く先に、アプリ名・問題（カード）の ID・その文の冒頭を、あらかじめ入れて渡す（https は URL の `title` と `body`、mailto は `subject` と `body`）。
- 利用者がスクリーンショットを添えて「ここ」と示せるようにする（2026-10-04 先生の要望）。本文の最後に添付のお願いを入れ、ボタンの近くにも添付できる旨を出す。
- 報告の先は、問い合わせ専用のメールアドレス（屋号のドメイン `support@aisunia.com`。Google Workspace のメールエイリアス）にする予定（2026-10-04 先生決定）。届くことを確かめるまでは、このリポジトリの GitHub Issues の新規作成ページにしておく。先生の個人のメールアドレスは使わない。差し替えは `reportUrl` の1行だけ。
- `reportUrl` が無い・https でも mailto でもないときは、ボタンを出さない。

**(5) 提供者の表示**（2026-10-04 先生了承）
- 「このアプリについて」の一番上に「提供：Aisunia」（屋号）とロゴ（`shared/images/aisunia-logo.webp`）を出す。

## 4. 問題の作り方（著作権と正確さ）

| | 決まり |
|---|---|
| 問題文 | **すべてオリジナルで作る。** Web の「過去問」サイト・市販問題集の文を写さない |
| 出題形式 | 公式の例題・サンプル問題に合わせる（G検定：4択・空欄補充・「最も適切／不適切なものを1つ選べ」） |
| Web の問題（2026-10-02 先生指示で拡張） | 出回っている問題を集め、**問われている知識・ひっかけの型・混同の組み合わせ**を抜き出して、それを応用した問題を作る。複数のサイトで繰り返し出てくる論点は重点として問題を厚くする。**文・選択肢の組はそのまま使わず書き直す**（写すと著作権に触れるおそれ）。Web の答えは誤りがあるので、必ず ②〜④ の出典で確かめ、食い違えば出典に従う。参考にしたサイトのURLは `docs/sources/` の調査メモに残す（アプリには出さない） |
| 公式の例題・過去問 | G検定は JDLA が20問を公開（https://www.jdla.org/certificate/general/issues/ ）、DX は運営がサンプル問題を公開。**形式の手本にするだけで、アプリに文を入れない**（アプリからはリンクで案内する） |
| 答えの根拠 | 公式テキストが手元に無い。**各問に出典URLを付ける**。優先順位：①試験のシラバス ②官公庁（e-Gov 法令・経産省・IPA・個人情報保護委員会・文化庁）③原論文・公式ドキュメント ④企業の公式サイト（事例） |
| 確認状態 | 各問に `verified`（出典を開いて根拠を確認した）／`unverified` を持たせる。`unverified` はアプリ上で印を出す |
| 法律の問題 | 条番号は e-Gov の原文で確認したものだけ書く。確認できない条番号は書かない |
| 図（2026-10-04 追加） | 解説に添える図は SVG でオリジナルに描く（教科書・論文の図をなぞらない）。数値・式・関係は `sources` の一次情報で確かめ、確かめられなかった数値は描かない。図の例の数値は問題の答えと同じにしない。決まりは §7-2 |

## 5. 体系的に学べること（このアプリの芯）

1. **シラバスを地図にする。** 大項目 → 中項目 → 小項目の木を「ステージ」として表示し、項目ごとの正答率・習熟度を色で見せる
2. **用語カード（概念カード）。** シラバスの小項目ごとに「一言で言うと／なぜ要るか／つながる用語／よくある混同」をまとめたカードを置く。問題を解く前後に読める
3. **解説は4点セット。** ①正解の理由 ②各誤答がなぜ違うか ③覚え方（語呂・対比表・因果のつながり） ④関連する用語カードへのリンク
4. **間違えた問題からの学び直し。** 間違えると、その問題の用語カードと「混同しやすい相手」を見せる。復習は間隔をあけて再出題（翌日・3日後・7日後・14日後）
5. **つながりで覚える。** 例：「勾配消失 → 原因はシグモイドの微分が小さいこと → ReLU で緩和 → さらにスキップ結合」のように、カード間を因果でたどれる

## 6. ゲームの要素（達成感）

| 要素 | 中身 |
|---|---|
| XP とレベル | 正解でXP。連続正解・初見正解・時間内正解でボーナス |
| ステージ | シラバスの中項目1つ＝1ステージ。小項目の問題を一定数正解でクリア、星1〜3 |
| 連続日数 | 毎日1問以上で連続日数が伸びる |
| バッジ | 大項目制覇・章の制覇・連続日数・模試の点数など。章の制覇バッジは、章（シラバスの中項目＝ステージ）ごとに1つ。その章のステージで星3を取ると獲得（章を完全にクリア）。大項目制覇（全ステージを星1以上）とは条件が違うので重ならない。取ったときにお祝いの画面が出て、未獲得のものはホームの「次の目標」の候補にも出る。すでにある12個と大項目制覇の取得記録は変えない（章の制覇は新しく足すだけ。すでに星3の章があれば、次に答えたときにまとめて取れる）。バッジ一覧の並びは、共通の12個 → 大項目 → 章の順。バッジ一覧・お祝いの画面・ホームの「次の目標」に、バッジごとの絵を付けてゲームらしくする。取ったものは色つき、取っていないものは灰色で薄く出す。絵の素材は、運営者（先生）が ChatGPT で作った画像（共通の12個は shared/images/badges/、章の制覇バッジは各アプリの images/badges/）。絵がまだ無いバッジは、これまでの記号の表示のままにする |
| 時間の練習 | 本番のペースで解く「秒数チャレンジ」モード。秒数は資格ごとに config で持つ（G検定 40秒＝100分÷145問、DX 37秒＝60分÷96問） |
| 模擬試験 | 本番の問題数・時間に合わせたモード（問題数が足りない間は縮小版） |
| 本番までの日数 | ホームに受験日までの残り日数と、未着手の範囲を出す |
| お祝いの画面 | レベルアップ・バッジ獲得・ステージの星が増えたとき・1日の目標を達成したときに、画面いっぱいのお祝い（大きなバッジやレベルの数字が弾む・紙吹雪が画面全体に降る）を出す。効果音と振動は設定がオンの人だけ。同時に複数あるときは1つずつ順に出す。下に「次はこれ：あと◯問で『◯◯』」を1つ出し、押せば始められる（始められない種類なら、ホームに戻るだけ）。閉じるボタンあり。動きを減らす設定の端末では動かさない。問題の途中では出さず、結果画面かホームに戻ったときに出す（解いている最中に中断させないため） |
| 効果音 | 正解・不正解・レベルアップ・バッジ獲得・星が増えたとき・1日の目標を達成したときに、それぞれ別の音を鳴らす。お祝いの画面（レベルアップ・バッジ・星・1日の目標）は、短いファンファーレ調のジングル（数秒の曲）で華やかにする。正解・不正解は短い音（1秒未満）で、解く流れの邪魔にしない。タイトル画面の『タップしてはじめる』を押したときにも、始まる感じの短いジングル（約1秒）を鳴らす（効果音がオンの人だけ）。初期はオフ。ファイルが取れない・読めないときは、昔からの簡単な電子音にきりかえ、学習は止めない |
| BGM | 学習に集中できる、静かでくり返せる曲を共通で6曲（資格ごとには分けない。ピアノ・アンビエント・鈴の音・軽いリズムなど、雰囲気が少しずつ違うもの）用意し、設定画面で『おまかせ（全曲を順番に流す）』か1曲を選べる（1曲を選んだら、その曲をくり返す。初期はおまかせ。各曲に短い日本語の名前と雰囲気を添える）。素材ごとに元の音の大きさが違うので、曲ごとに補正の倍率を持たせ、同じ音量の目盛りならどの曲もほぼ同じ大きさで聞こえるようにする（目盛り最大でも、どの曲も音が割れない範囲に収める）。流す場面は問題を解いている画面（ステージ・復習・秒数チャレンジ・模擬試験）だけ。ホーム・地図・カード・設定では流さない（開くたびに鳴ると驚かせるため。学習中だけ鳴る）。初期はオフ。スマホのブラウザは画面を一度さわるまで音を出せないので、オンのときは最初の操作のあとから流す。アプリが裏に回ったら止め、戻ったら続ける。設定画面で『試しに聴く』ができ、試しに聴いている最中に曲を選び直すと、その曲に切り替わる |
| 音の設定 | 設定画面と、タイトル画面の右上の歯車（押すとポップアップで開く）の両方で、効果音と BGM それぞれのオン／オフと音量（0〜100）を変えられる。初期値は、効果音オフ・音量70、BGM オフ・音量40・BGM の曲はおまかせ。これまでの『効果音』のオン／オフは、そのまま効果音のオン／オフとして引き継ぐ（古い記録で効果音がオンの人はオンのまま）。範囲外・不正な値は、範囲内に直すか初期値に戻す（BGM の曲の選択は、古い記録に無い・今は無い曲を指しているときは『おまかせ』に戻す）。音量を動かすと、効果音はその場で試しに鳴らし、BGM は鳴っている最中に大きさが変わる。振動は別の設定のまま。タイトル画面のポップアップの中身は、設定画面の『音』のカードと同じ部品で、変えた設定は設定画面と同じように保存する（配色など音以外の設定は、ポップアップには入れない）。ポップアップは、閉じるボタン・背景を押す・Esc キーで閉じ、開いている間は Tab キーの移動がポップアップの中だけを回る。『BGM を試しに聴く』は、ポップアップを閉じたら止まる。歯車を押すことも『最初の操作』として扱い、ポップアップの中の効果音や試し聴きがすぐ鳴るようにする |
| 音の素材 | 効果音も BGM も、**CC0（再配布・商用・改変が自由で、表示も不要）の素材だけ**を使う。公開リポジトリに入れるので、『フリー素材』でも再配布の禁止・クレジット必須・独自ライセンスのものは使わない。素材ごとに、配布ページでライセンスを確かめ、ファイル名・作者・配布ページ・確かめた日を `docs/sources/audio-licenses.md` に記録する（記録に無い音のファイルは置かない）。BGM は1曲3MB以下。効果音は小さいのでオフライン用に先に取り、BGM は初めて流したときに取ってキャッシュに入れる（初回の読み込みを重くしないため）。形式は ogg か mp3 |
| 次の目標 | ホームに、いちばん近い目標を3つまで、進み具合の棒つきで出す（例：「7日連続まで あと2日」「レベル5まで あと40XP」「ステージ『◯◯』の星3まで」）。「近さ」は、達成までの残りの割合が小さい順。バッジ一覧の未獲得にも「いま 73/100」の棒を付ける |
| タイトル画面 | アプリを開くと、まずタイトル画面を出す（ホームの前）。背景は資格ごとの画像（config.json の titleImage。無い・読めないときは、テーマ色のグラデーションの仮の背景）、上の3分の1にアプリ名（config.json の name）を重ね、受験日までの日数を小さく添える。画像の上の文字は、影と暗い膜で、明るい配色・暗い配色のどちらでも読めるようにする。下に読み込みのゲージを出し、問題データ（index.json が並べるファイル）を何個中何個読んだかで伸ばす（個数が分かる前は0のまま）。読み込みが終わったらゲージの位置に『タップしてはじめる』のボタンを出し、押すとホームへ進む。データがキャッシュから一瞬で読めるときも、ボタンを押すまでタイトル画面で待つ。このボタンが『最初の操作』になるので、効果音か BGM がオンの人は、押した瞬間に音を使える状態にする（BGM を流す場面は、これまでどおり問題を解く画面だけ）。URL でホーム以外の画面（例: 問題の途中のページ）を指定して開いたときも、タイトル画面を経由して、押したあとにその画面へ進む。読み込みに失敗したときは、ボタンの代わりに、原因と『再読み込み』を同じ画面の上に出す。動きを減らす設定の端末では、ゲージの伸び以外のアニメーションを止める。右上に歯車のボタン（押せる大きさは48px以上）を出し、読み込み中でも押せる。押すと音の設定のポップアップが開く（中身は『音の設定』の行のとおり）。『タップしてはじめる』を押すと、始まる感じの開始のジングルを鳴らし（効果音がオンの人だけ。オフなら鳴らさない）、音とあわせて画面にも演出を付ける（ボタンが光って輪がはじけ、画面が白く明るく抜けてからホームに切り替わる。全体で1秒前後で、待たされる感じにしない）。動きを減らす設定の端末では、演出をせず、すぐホームに切り替える。BGM はこれまでどおり、ホームでは流れない（問題を解く画面だけ） |
| 1日の目標 | 1日に答える問題数の目標。初期値は10問（ステージ1回と同じ重さ）。設定画面で変えられる。ホームに今日の進み具合を出す。達成したらお祝い（1日1回。日付の区切りは連続日数と同じ、端末の日付）。模擬試験で答えた問題も数える。目標を下げて、すでに超えていた場合もその場でお祝いが出る（その日の1回だけ） |
| キャラクター | 学ぶ人を応援して、ゲームらしくするために、2人のキャラクターを置く。素材は、運営者（先生）が ChatGPT で作った画像（12枚。shared/images/characters/）。**柴犬**（赤いバンダナをした、屋号 Aisunia のマスコット）と、案内役の**先生**。**まだ名前は無い**ので、名前を出す文言は作らない（画面に「先生」「柴犬」とも書かない）。一言の文言は1か所（shared/js/lib/characters.js）にまとめ、名前が決まったらそこへ差し込む。**1画面に出すのは1人まで**、小さく添える（押せる場所・文字を隠さない）。絵は飾りなので alt は空にして読み上げの対象から外し、意味のある言葉は文字で出す。出るときは、ぴょこんと飛び出す（下から跳ね上がって、ぽよんと弾んで止まる。0.5秒ほど）。バンザイと拍手は大きめに弾み、「大丈夫」の先生とうとうと柴犬はやさしくふわっと出て、応援の柴犬は元気よく跳ねる。吹き出しの一言は、絵が出たあと少し遅れてぽんと出る。出たあとも、2〜3px だけゆっくり上下し、ときどき小さく傾く（文字を読む邪魔にならない小ささ）。動きを減らす設定では、動きを全部止めて、そのままの姿で出す。<br>**柴犬＝お祝いと応援。** ①ホームの上：ふだんはあいさつ。最後に学習した日から1日まるごと休んでいたら（日付の差が2日以上）、うとうとして「おかえり」の一言。まだ学習していない人はあいさつ ②お祝いの画面の隅：レベルアップと1日の目標はバンザイ、バッジと星の増加は拍手（今のお祝いの絵は置き換えず、添えるだけ） ③問題で不正解が3問続いたとき（その後は6問め、9問め…と3の倍数のとき）：解説の上に応援の一言と絵 ④「このアプリについて」の提供者（Aisunia とロゴ）の近く：マスコットの紹介<br>**先生＝解説の案内。** ①問題の解説の「正解の理由」の横：正解なら丸、不正解なら「大丈夫」 ②「覚え方」の横：指さし ③模擬試験の結果：正答率70%以上は拍手、70%未満は「大丈夫」の一言。結果の見直しの一覧の中の解説と、柴犬が応援を出している解説には、先生を出さない（1画面に1人まで）。<br>考える姿の柴犬と先生、あいさつの先生の素材も置いてあるが、いまは使う場面が無い |

## 7. 問題データの形（両資格共通）

`<資格>/data/` に置く。JSON。

```json
{
  "id": "G-DL-ACT-001",
  "syllabus": ["技術分野", "ディープラーニングの概要", "活性化関数"],
  "format": "single",
  "difficulty": 2,
  "stem": "問題文",
  "choices": ["A", "B", "C", "D"],
  "answer": 1,
  "explanation": "正解の理由",
  "whyWrong": ["Aが違う理由", null, "Cが違う理由", "Dが違う理由"],
  "memoryTip": "覚え方",
  "concepts": ["CONCEPT-ID"],
  "sources": [{ "title": "出典名", "url": "https://..." }],
  "status": "verified"
}
```

- `format`: `single`（1つ選ぶ）／`not`（適切でないものを選ぶ）／`fill`（空欄補充）／`scenario`（場面を読んで判断。DX向け）
- `answer` は0始まりの添字。`whyWrong` の正解位置は `null`
- 任意の欄 `figures`: 図の ID の配列（例 `["fig-g-activation"]`）。問題にも用語カードにも置ける。決まりは §7-2
- 用語カードは `concepts.json` に `{ id, syllabus, title, oneLine, why, links:[{id, relation}], confusions:[{id, point}], sources, status }`
- シラバスの木は `syllabus.json`
- 資格ごとの設定（名前・受験日・模試の問題数と時間・配色）は `<資格>/config.json`

### 7-2. 図（SVG）の決まり

文字だけでは分かりにくい用語・問題の解説に、図を添える。計画と図ごとの根拠は `docs/sources/figure-plan.md`。

**データ**

- 用語カードにも問題にも、任意の欄 `figures`（図の ID の配列。無ければ図なし）を置ける。例: `"figures": ["fig-g-activation"]`
- 図の ID は `fig-` で始まる小文字の英数字とハイフン（例 `fig-g-confusion-matrix`）。資格の印を入れる（G検定は `fig-g-`、DX は `fig-dx-`）
- 図の本体は `<資格>/data/figures/<図のID>.svg` に置く。1枚の図を複数のカード・問題から使い回す。G検定と DX で似た図があっても、資格ごとに別の ID で置く
- 用語カードの画面（用語の説明の下）と、問題を解いた後の解説（「正解の理由」の下）の両方に出す。用語カードが図を持っていても、問題の `figures` が空なら問題の解説には出さない（問題ごとに、答えの理由が分かりやすくなる図だけを指定する）

**描き方**

| | 決まり |
|---|---|
| 作り手 | SVG をこちらで手書きする。**中身もオリジナル**（教科書・論文の図をなぞらない）。外から来た文字列は混ぜない |
| 数値・式・関係 | そのカードの `sources` の一次情報で確かめたものだけを描く。**確かめられなかった数値は描かない**。取得は curl（PDF は pdftotext）で全文を取って検索する |
| 例の数値 | 図の例（混同行列の件数、面積図の割合など）は、そのカードに紐づく問題の答え・選択肢に出る数値と同じにしない（解説で答えを先に見せない）。計算は自分でも確かめ直す |
| 大きさ | `viewBox` は幅 360 以下（標準は幅 320）。スマホの縦画面（幅360〜390px）で拡大せずに読めるよう、図の中の文字は画面上で 12px 相当以上（幅320の図では13）。横に長い図は避け、縦に積む |
| 配色 | 色は SVG に直書きせず、共通 CSS（`shared/css/app.css` の「図」の節）のクラスで付ける。クラスは既存の CSS 変数（`--text` `--accent` `--ok` `--ng` `--warn` など）を使うので、明るい配色・暗い配色の両方で見える。**色だけで区別させない**（線の種類・ラベルも併せて付ける） |
| 読み上げ | ルートの `<svg>` に `role="img"`、`<title>`（図の題）と `<desc>`（図が言っていること）を付け、`aria-labelledby` で結ぶ。題は画面にも見出しとして出る |
| 取り込み方 | 外部の画像として読まない（CSS 変数が効かない）。アプリが SVG の文字を取り、安全を確かめて画面に取り込む。取り込めない・読めないときは「図を読み込めませんでした」と出し、解説の文字は通常どおり出す |
| 禁止 | `<script>`・`<foreignObject>`・`<style>`・`style=`・イベント属性（`onclick` など）・`#` で始まらない `href`・外部への参照（`http` など）・`<image>` |
| オフライン | サービスワーカーがインストール時に、データが指す図をすべて取って保存する |

**検査**（`tools/check-data.js`、DX は `tools/check-data-dx.js` も同じ検査を持つ）

- `figures` が文字列の配列で、各 ID が形式どおりで、対応する SVG が `data/figures/` に実在すること
- `data/figures/` の SVG すべてについて、上の禁止事項が無いこと・`viewBox` が幅 360 以下であること・`role="img"` と `<title>`・`<desc>` があること
- どのカード・問題からも使われない SVG は警告（NG にはしない）

見ていないもの: 図の中身の正しさ（数値・式が出典と合うか）・文字の大きさと見た目（画面で目視する）。
