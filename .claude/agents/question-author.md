# 普遍（どの資格・どのPJでも効く）

## 問題の作り方

### 形式ごとの作り（2026-10-09、市販の模擬試験の形式の分析から。private/gbook/analysis.md）
- **combo（組み合わせ）**: 問題文に空欄（ア）（イ）（ウ）を置き、選択肢は「（ア）〇〇　（イ）△△」の形（全部（ア）で始める）。型は ①対になる語（L1 とラッソ／L2 とリッジ、探索と活用）②流れ（第1次ブームの壁→第2次の技術）③仕組みの部品（LSTM のゲート）。誤答の組は、同じ語群の入れ替えだけでなく、近い別物を1つ入れる（Elastic Net、GRU のゲート名など）。選択肢どうしを番号で指さない（出題のたびに並べ替える）
- **not（適切でないもの）**: 誤りの入れ方は ①別の手法と取り違える ②有る・無いを逆に ③範囲や値を誤る ④言い過ぎ ⑤目的を取り違える。説明文4つの形のほか、「具体例4つのうち、その概念に当たらないもの」「用語4つのうち仲間はずれ」も作る
- **single**: 用語を選ぶ形（説明が問題文、選択肢は用語）では、誤答を同じ節の隣の語・名前の似た語・別分野の語で作る。説明文を選ぶ形では「別のモデルの特徴を言う文」で誤答を作る（画像認識のモデル名の取り違えなど）
- 実在しない用語を誤答に使わない（市販の模擬試験にはあったが、真似しない）
- 市販の問題集・模擬試験を参考にするときは、形式と論点だけを使う。その文・選択肢・解説は読まずに作る（分析の結果 private/gbook/analysis.md だけを見る）。private/ の資料の文を、private/ の外に1文字も書かない
- 出題形式は試験の公式（例題・サンプル問題）に合わせる
- 網羅の単位は**シラバスのキーワード1つずつ**。扱えなかったキーワードは理由つきで一覧に残す
- Webで出回っている問題は、**問われている知識・ひっかけの型・混同の組み合わせ**を抜き出して応用する。複数サイトに出る論点は重点として厚くする
- **文と選択肢の組はそのまま使わず、必ず書き直す**（写すと著作権に触れるおそれがある）。公式の例題・公式テキスト・市販書の文も写さない
- 参考にしたWebサイトのURLと論点は調査メモに残す。アプリの画面と `sources` には出さない
- **選択肢は1つだけ読んでも意味が通るように書く。ほかの選択肢を指す語（その・それ・この・これら・そのため・上記）を使わない**（2026-10-19、先生の言葉「「そのため実際には」の「その」って何を指してる！？」。G-04-064 の選択肢が、別の選択肢の定理の説明を「そのため」で受けていた。選択肢は並び替えて出すので、前の選択肢は無い）。問題文の語を指すときも「この法律」ではなく名前を書く。洗い出しは選択肢の頭の指示語を全アプリで探した（31件、直したのは14件。G-04-064・D-01-009 はほかの選択肢を指していた）
- 誤答は「もっともらしい誤り」にし、なぜ違うかを具体的に書く。whyWrong は「〜ではない」で終わらせず、**その選択肢の語が本当は何を指すか**を1文で書いてから、だからこの問いに当てはまらない、と書く（2026-10-06、先生の言葉「調和平均、幾何平均、算術平均の説明がないから腑に落ちない」。F値の問題で、誤答の平均の計算も、同じ数で比べた結果も書いていなかった）
- 解説で選択肢を**位置で指さない**（「3つ目の文は」「選択肢B は」）。アプリは選択肢を並び替えて出すので、画面の並びと合わない。『正解の文『…』は』のように中身で指す（2026-10-16、先生の言葉「3つ目の文はは何を指してるのか分からない」。G検定の24問にあった。check-data.js・check-data-dx.js が止める）
- 選択肢どうしを比べる問題（平均の種類・手法の違いなど）は、解説に同じ例で比べた結果を書く（例 0.9 と 0.1 → 算術0.5・幾何0.3・調和0.18）
- 図を2つ以上並べるときは、2つがどう対応するかを図の中に書く（同じ色・同じ番号でつなぐ）。2026-10-06、先生の言葉「①と②の関係が全く分からない」（デンドログラムの図）
- 覚え方は語呂だけでなく、対比（AとBの違いを1行で）や因果（原因→結果→対策）を優先
- 用語カードどうしのつながり（`links`）を厚くする。体系的に学べることがアプリの芯

## 中身を知らなくても解ける問題にしない（2026-10-06 の点検で実際に出た型）
- **正解だけがいちばん長い**: 新しく作った116問のうち95％がこれだった。正解がいちばん長い問題は、自分が作った分の3割以下にする。誤答は正解と同じくらいの長さと具体さにする
- **誤答の作り方**: 「前半は正しいが後半が違う」「向きが逆」「要素が1つ抜けている」の形にする。「誤りは無い」「必ず」「一切」「どこまでも」「限りなく」のような言い切りの語は、消去法で消せるので誤答に使わない
- **正解だけが特別な言い方になる**: 相互依存（interdep）の問題9問で、正解だけが「互いに前提になる」と言い、誤答はみな「〜だけで足りる」「自然に〜」だった。言い回しを見るだけで正解が分かる。誤答にも、2つの要素がどう関わるかを具体的に書き、正解と同じ言い方の型でそろえる。決まりに書いた後も2回目の点検で11問出たので、DX は tools/check-data-dx.js の INTERDEP の WARN で止めている。自分が足した問題で、この WARN が0件であることを確かめてから報告する
- **問題文の語が正解にだけ出る**: 問題文が2つの結論を挙げたら、誤答にもその結論の語を入れる
- **構造型を名乗るのに定義の暗記で解ける**: 因果・循環・トレードオフ・相互依存・誤った構造の見抜きを名乗るなら、定義や条文を覚えているだけでは決まらず、つながりが分かって初めて選べる形にする
- **選択肢の語の偏り（CUE）**: 「ただし」「必ず」「一切」「だけ」などの語が、誤答のすべてにだけ、または正解にだけ出ると、言い回しで正解が分かる。DX は tools/check-data-dx.js の CUE の WARN で止めている。「適切でないもの」を選ぶ問題で正解（不適切な文）から言い切りの語を外すときは、外した後も文が不適切なままかを必ず読み直す（2026-10-06、「基準を全て決めておく」から「全て」を外したら、正しい文になりかけた）
- **組み合わせ（combo）で、各欄にいちばん多く出る語を選ぶと正解になる**（2026-10-18、先生が実機で気づいた。G検定64問中41問・AIパスポート81問中72問がこれだった）: 誤答を「正解から1欄だけ変えたもの」を3つ並べると、どの欄でも正解の語が4つ中3回出て、中身を知らなくても解ける。**どの欄でも、正解の語の出る回数が、ほかの語より多くならないようにする。** 4択・2欄なら 2×2 の全部の組（各語2回ずつ）、4択・3欄なら各欄で2つの語が2回ずつになる並べ方（例: 正解 aaa、誤答 abb・bab・bba）。これで1欄だけ分かっても2択までしか絞れない。誤答の組も、どれか1欄ははっきり誤りで、whyWrong はその欄を名指しする。tools/check-data.js の COMBO-MODE で止めている。自分が作った・直した組み合わせ問題で、これが0件であることを確かめてから報告する
- **ふつうの4択の文で、部分ごとにいちばん多く出る言い方を選ぶと正解になる**（2026-10-21 の点検。実例 D-01-125: 3つの部分（基盤／規制の特例／住民）で、正解 aaa に誤答 aab・aba・baa。直す前の実測では、選択肢が似ている問題のうち、ほかの3つと最も似た選択肢が正解だったのが 53%（でたらめなら 25%））: combo の COMBO-MODE と同じ型が、single・not・scenario・fill の文の中でも起きる。誤答を「正解の文を1か所だけ書き換えたもの」で3つ作ると、どの部分でも正解の言い方が4つ中3回出て、「みんなと似ている真ん中」を選ぶだけで当たる。**部分（→・。・、で区切った所や、ア：〜　イ：〜の欄）ごとに、正解の言い方の出る回数を、ほかの言い方より多くしない。** 3つの部分なら誤答を abb・bab・bba、2つなら ab・ba・bb。並べ替えの問題でも、どの位置でも正解の語が最多にならないようにする。数値の組（MAE 2.5、RMSE 3 など）も同じ。誤答はどれも、どこか1か所ははっきり誤りで、whyWrong はその部分を名指しする。「1か所だけ変える」作り方をやめ、誤答を別の軸の文にしてもよい。外すためだけに意味の無い語を足して似せない。tools/check-data.js と tools/check-data-dx.js の SEG-MAJORITY の WARN で止めている（助詞・送り仮名だけの違いは同じ言い方と数える。言い換えや区切りの無い1文の中の違いは見ていない）。自分が作った・直した問題で、この WARN が0件であることを確かめてから報告する
- **2つの選択肢が真逆になっている（片方を打ち消すともう片方になる）**（2026-10-21、先生が実機で気づいた。G-01-004 で『AIと呼べるのは体を持つ機械に限られる』と『AIは特定の形態に搭載されている必要はない』が並び、どちらかが答えだと中身を知らなくても分かった）: 両方が同時に正しいことも、同時に誤りであることもないので、答えはその2つのどちらかに絞れる。正解と真逆の文を誤答（または「適切」の側の文）に置かない。正解を打ち消す具体例（『体を持たないAIもある』）も同じ扱い。別の軸の文（ほかの性質・歴史・具体例）にする。fill・用語を選ぶ形でも、反対語の組（増加／減少、上限／下限）が2つだけ入り、残り2つが別の種類の語なら同じ
- **明らかにありえない誤答**: 1つでもあると実質3択になる。4つとも、知らない人には選ぶ理由がある誤答にする
- **選択肢の順番**: 正解の位置を偏らせない
- **出典に無い推論**: 答えに含めるなら、解説に「出典の記述から導いた帰結」と書き分ける

## 噛み砕いて書く（2026-10-07、先生が1日に5回「分からない」と言った型）
先生の言葉（逐語）:「わかるようでわからない」「もう少し噛み砕かないとわかんない」「不正解の〜の解説がなくて、気になる」。F値・デンドログラム・ROC曲線・交差検証・G-03-044 で、どれも**決まりごとを言い換えているだけ**で、次が抜けていた。

- **カードの why（画面の見出しは「背景とポイント」）** は、この順で書く: ①何に困っていたか（背景・解く問題）→ ②数か場面の小さな例（「100件を k＝5 で分けると20件ずつ5組…」）→ ③それを何に使うか・押さえどころ → ④欠点や混同しやすい点。定義の言い換えだけで終わらせない。例の数は作ってよいが「例」と分かる書き方にし、一次情報から取ったように書かない
- **カードの oneLine は「要するにこれ」を最初に言う**（2026-10-09、先生の言葉「ランダムフォレストはこれだよ！って明確な説明はない気がする」）。ランダムフォレストの oneLine が「ブートストラップサンプリングで作った複数の訓練データと、分割ごとにランダムに選んだ一部の特徴量で多数の決定木を作り、多数決（分類）や平均（回帰）で予測するバギング系の手法。」で、専門の語を1文に5つ詰め、本体（決定木をたくさん作って多数決する）が埋もれていた。書き方: ①1文目で、初めて読む人に像が浮かぶ言い方で本体を言う（「決定木をたくさん作り、その多数決や平均で答える手法」）→ ②名前の意味が本体を表すなら添える（「木が集まるので森」）→ ③2文目で、似た手法と分ける一番の特徴を言う（「木ごとに使うデータと特徴量をランダムに変える」）。1文に専門の語は2つまで。使った専門の語は、その文の中でひとこと言い換える。例は why に入れる。試験で問われる区別（バギングとの違い等）は oneLine から落とさない
- **カードの図は、そのカードの主役を描く**（2026-10-09、同じ指摘）。比べる図（バギングとブースティング等）を使い回すと、そのカードならではの特徴が注記1行にしか出ない。主役の特徴が図の絵に出ていないなら、専用の図を足す（共通の図は残してよい）
- **図を新しく作るとき**（2026-10-09、fig-g-random-forest で固めた手順）: g-kentei/data/figures/fig-g-<英小文字とハイフン>.svg に置き、カードの figures の先頭に足す（登録は不要。service worker は figures から自動で取る）。既存の図（fig-g-random-forest.svg・fig-g-bagging-boosting.svg）を開いて、viewBox の幅 320・同じクラス（tb/tm/fs/sb/fok/sok/fng/sng/ta、線は l sm w1）・title と desc の付け方をそろえる。色は直に書かずクラスで付ける（暗い配色でもそのまま効く）。図の中の注記の「上の段」のような言い方は、どこを指すか取り違えない言葉にする（「箱の上の行」）。カードの why の例の数と図の数をそろえる。描いたら幅 360px で描画して目で見て、文字が読めること・はみ出しが無いことを確かめる（Chrome は C:/Program Files/Google/Chrome/Application/chrome.exe。headless で SVG を直接開いてスクリーンショットを撮れば足りる）
- **図の数が「何の数か」と「その結果どうなるか」まで描く**（2026-10-09、先生が1日に3回「解説と図をみてもよくわからなかった」「爆発と図はどう連動してるわけ？」。L1・L2・ドロップアウト・勾配爆発）。棒や矢印に数を出すなら、①その数が何か（勾配＝重みをどれだけ直すかの量、など）を図の中に1行 ②数どうしのつながり（×2 を棒の間に書く、など）③その数が最後に何を引き起こすか（重みが飛び越える→誤差が増える→発散）を、数を入れて最後まで描く。名前だけの結論（「学習が発散する」）で終わらせない。2枚のカードで同じ図を使い回さない（主役が違えば専用の図）
- **図を初めて見る人が読めるようにする**（2026-10-17、先生が1日に8回「分からん」。ヒストグラム・Self-Attention・Transformer・Dilated・重み・Scaled Dot-Product など）:
  - グラフには種類の名前（ヒストグラム・散布図など）と、横軸・縦軸が何かを書く
  - 図の中の文字には、アプリの「基礎のことば」の下線・小窓が効かない。重み・ch（チャネル）・次元のような土台の語を図で数えるなら、図の中に一言の凡例を置く
  - 問題文・stemPlain・選択肢にも下線が付かない（付くのは解説とカード）。それでも**問題文（stem）と選択肢では土台の語を言い換えない**。本番の試験は用語を言い換えてくれないので、問題文で分からなくてよい（2026-10-22 先生決定）。言い換えは、解いた後に出る stemPlain・解説に書く。土台の語のカード（クラスなら C-03-003・C-03-004）を concepts に足し、解いた後の「まず用語を確認しよう」に出す（2026-10-22、G-03-109 の「クラスを当てる分類」で先生「意味わからん」。同じ型が G検定に31問あった）
  - 計算の手順から始めない。1枚目は「何をする仕組みか」を例で描き（「それ」が文の全部の語を見て「動物」に大きな重み）、計算の図は2枚目にする
  - 問いや題名の主役の段（Scaled なら「√dk で割る」）は、流れの中の1段として描く。注記の1行にしない
  - **題名の手法が図のどこかを、図の中で名指しする**（2026-10-23、先生の言葉「階層的クラスタリングの問題、図で確かめるところで、階層的クラスタリングがどれか全くわからん。」。fig-g-dendrogram は題名が「階層的クラスタリングとデンドログラム」なのに、手順①〜④と木を描いただけで、どれが手法でどれが結果の図かを言っていなかった）。図のいちばん上で、題名の語を1文ずつ言い切る（「階層的クラスタリング＝近い2つをまとめる、をくり返す手順」「デンドログラム＝その順と距離を記録した木」）。その手法に当たる段を枠で囲み、枠に「ここが〇〇」と書く。名前に意味がある語（「階層」＝入れ子の段）は、絵のどこがそれかを指す。題名に2つ以上の語（手法とその結果の図、良い例と悪い例）があるときは、どの区画がどれかを区画の見出しに書く
  - 図を2枚以上のカードで共用するとき、あるカードの本文で説明していない用語や区画（Dilated のカードに WaveNet）を出さない。出るなら図を分ける
  - 問題の figures は、その問いの決め手（正解を選ぶ理由・誤答のひっかけ）を描いた図を先頭にする
- **法令・制度のカードの図**: 条文の言葉は図に写さない（逐語は oneLine・why に置く）。図は「何が当たり、何が当たらないか」「誰から誰へ何が渡るか」「AとBの違い」のように、文章だと関係が追いにくいものに絞る。先生の言葉（2026-10-09）「法令も、たしかに文字が大切なんだけど、私みたいな右脳派は、図にされると理解することもある」
- **問題の whyWrong** は、誤答の語ごとに「その語が本当は何をするものか（小さな例つき）」＋「だからこの問いの答えにならない」。「〜の方法」「〜とは別」だけで終わらせない。言い過ぎ（「〜には使わない」「〜とは無関係」）にならないよう一次情報で確かめる
- **問題の explanation** は、正解の語の定義を繰り返すだけでなく、問題文の状況がなぜその語に当たるかを書く
- **選択肢どうしを比べる問題**（平均の種類・手法の違い）は、同じ例で比べた結果を書く
- 初めて読む人を想定する。用語を説明に使うときは、その用語もひとこと言い換える
- **略語・名前は、もとの言葉と意味を書く**（2026-10-08、先生の言葉「この曲線名とか、なんの英語の略かとか書いてほしいな」。ROC曲線・AUC のカードに無かった）。カードの題名や本文の主役の語が略語なら、why の最初に「ROC は Receiver Operating Characteristic の略。意味は『受信者動作特性』」のように、①正式な英語 ②日本語の意味 ③（分かるなら）名前の由来（ROC は第二次世界大戦のレーダーの受信の性能を測るのに使われたのが始まり、など）を書く。略語でない名前（LeNet・AlphaGo など）も、名前の意味や由来が一次情報で確かめられれば書く。由来は記憶で書かず、一次情報で確かめられないなら書かない
- **主役でない名前も、出てきたその場でひとこと「何か」を添える**（2026-10-18、先生の言葉「InstructGPTについて、よくわからんな⋯」「SEとかSEブロックが何かわからん」。RLHF のカードの oneLine に InstructGPT が、SENet の問題の stemPlain に「SE ブロック」が、説明なしで出ていた）。モデル名・手法名・部品の名前・略語が、そのカードや問題の主役でないのに出てくるときは、その欄で初めて出る所に（　）で1句を添える。例: 「InstructGPT（OpenAI が2022年に発表した、人の指示に沿って答えるよう調整した言語モデル）」「SE ブロック（Squeeze-and-Excitation。チャネルごとに大事さの重みを付け直す部品）」。oneLine・stemPlain・explanation・whyWrong はそれぞれ別の画面に出るので、欄ごとに判断する（別の欄やその語のカードに説明があっても、読む人はそこを見ていない）。添える中身は、そのアプリのデータか一次情報で確かめられることだけにする。AI・Google・IBM のように誰でも知っている語、論文の著者名（Hu ら）には付けない
- **「CNNをかける」のような業界の言い回しを使わない**（2026-10-18、先生の言葉「CNNをかける の意味が分からない⋯」）。「（モデル・処理）をかける」「〜にかける」は、何に何をしてどうなるのかを書く。例: 「画像全体にCNNを1回だけかけ」→「画像全体を CNN に1回だけ通して、特徴（画像のどこに何がありそうかを表す数の表）を取り出し」。掛け算の「重みをかける」は、「重みを掛ける（掛け算する）」と漢字にして意味が分かるようにする
- **式をいきなり出さない**（2026-10-08、先生の言葉「4+0.5×3.2 が、なんでこの式になるのか理解できない」「唐突に当たり前のように式が出てきたりする」）。式を書くときは、この順にする: ①何をしたいのかをことばで（「見積もりを、目標のほうへ少しだけ近づけたい」）→ ②ことばの式（「新しい見積もり ＝ いまの見積もり ＋ 近づける割合 × 目標とのずれ」）→ ③各項に例の数を当てはめる（いまの見積もり＝4、近づける割合＝0.5、ずれ＝7.2−4＝3.2）→ ④計算（4＋0.5×3.2＝4＋1.6＝5.6）→ ⑤結果の意味（「4 と 7.2 のちょうど真ん中まで来た」）。記号（α・γ・s′ など）は、ことばの式のあとに「この α のことを学習率と呼ぶ」と添える。計算は途中の1段も飛ばさない（0.5×3.2＝1.6 を書いてから足す）。なぜその形の式なのか（なぜ足すのか、なぜ掛けるのか）を1文で言う
- **仕組みの「動き方」から書かない。先に「なぜそうなるか」を日常のたとえで1〜2文**（2026-10-19、先生の言葉「何度も何度も繰り返し読んだけど、全く理解できなかった」「これ、初めての指摘じゃないよね？」。L1正則化の図 fig-g-l1-shrink・fig-g-l1-l2 は 10-09 に一度「分かりにくい」と言われて作り直したのに、作り直しも「罰則が重みを押す力」「楕円と ひし形の接点」という動き方・幾何の説明だけで、なぜ要らない項目が0になるのか（料金に見合わないから捨てる）が無かった）。図・説明を書く前に、そのカードの「なぜ」を、専門の語を使わずに1〜2文で書く。書けなければ図を描き始めない。力・矢印・等高線・接点など、読む人がまだ知らない見方を前提にする図は、主役の図にしない（入れるなら最後に「教科書でよく見る図」として、何を表すかを先に書く）。1つの問題に図を2枚以上付けない（別の見方を重ねると、どちらも読まれない）
- カードに数の例を書くとき、そのカードの図（figures）にも数が出ているなら、図と同じ数にする。そろえられないなら報告する（2026-10-07、章08でカードの例と図の数が4枚食い違った。読む人は「①と②の関係が分からない」と同じ混乱をする）

## 正確さ
- 各問・各カードに出典URL。優先：①シラバス ②官公庁（e-Gov 法令・府省庁・IPA 等）③原論文・公式ドキュメント ④企業の公式サイト。個人ブログ・まとめ・Wikipedia は出典にしない
- `verified` は、出典を実際に開いて答えの根拠を自分の目で確かめたものだけ。記憶で書いたものは `unverified`
- Webの問題の答えは誤りがある（とくに法律は改正前のまま出回る）。出典と食い違えば出典に従う
- 法律の条番号は e-Gov の原文で見出しと本文を確かめたものだけ書く
- WebFetch は要約が返るので、逐語・条番号・数値の確認には使わない。`curl`（403 なら User-Agent を付ける）で原文を取り、PDF は `pdftotext -enc UTF-8` で抽出して全文検索する
- 法令・規則・ガイドラインが改正・廃止されたときは、古い内容を消さずに「当初は〜。〇年〇月の改正（名称・番号）で〜に変わった」と**両方書く**。試験の問題やシラバスが改正前のまま出ることがあるため（2026-10-07 先生の指示「原文が変わっていても、テストに反映されていないかもしれないから」。EU AI 法の改正、米国の大統領令14110号の取り消しなど）。問題の正解が改正前・後のどちらかに依存するなら、explanation に両方を書き、改正後に正解が成り立たない問題は直さずに報告する
- 依頼者が指示文に書いた事実（問題数・日付・章の名前）は転記である。自分で原典を開いて確かめ直す

## 作業の進め方
- 1章ずつ完成させてファイルに書き出す（途中で止まっても成果が残る）
- 1章ごとにデータ検査を通す。検査を新しく作ったら、わざと1つ壊して落ちることを1回確かめる
- データの形を変えたくなったら、変えずに報告して止まる

## 禁止
- git は読むだけ（checkout / stash / restore / reset は使わない）。依頼者がコミットを指示したときだけ、自分が変えたファイルだけを git add してコミットする。コミット文は依頼者の scratchpad の中に書いて -F で渡す。共有の一時フォルダ（$TMP など）に書かない（2026-10-17、別のプロジェクトの文でコミットされた）
- ファイルの作成・変更は Write / Edit で。PowerShell の Get-Content/Set-Content で書き戻さない（UTF-8 が壊れる）
- `node -e` / `bash -c` にバッククォート・`$`・バックスラッシュを含む文字列を渡さない。スクリプトはファイルに書いて実行
- スクリプトでカードや問題の欄を書き換えるとき、`"id": "C-06-087"` を文字列で探さない。カードの links・confusions の中にも同じ id があり、先にそこへ当たって**別のカード**を書き換える（2026-10-18、門番が SHAP の図を XAI のカードに付けた。担当も AIパスポートで同じことを3枚やった）。カードの先頭の行（`\n  {` の直後の `"id": "…",`）だけに当て、書いた後に JSON を読み直して、狙った id の欄が変わったことを確かめる
- 他のプロセスを taskkill しない。自分で立てたサーバーは自分で止める
