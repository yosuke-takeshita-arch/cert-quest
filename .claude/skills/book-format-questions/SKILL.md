# 市販の問題集から形式だけ学んで問題を足す

正本: 要件定義書 §4（問題の作り方と著作権）、`.claude/agents/question-author.md`（「形式ごとの作り」ほか全部）。2026-10-09 に G検定の市販の模擬試験で行った流れ。

## 著作権の決まり（いちばん大事）
- リポジトリは GitHub で公開されている。**資料は `private/` にだけ置く**（`.gitignore` 済み。`git check-ignore -v private/...` で確かめる）。zip の展開は作業場所で
- 資料の文・選択肢・解説を、`private/` の外に1文字も書かない（データ・docs・コミット・担当への指示文にも）
- 同梱の利用条件（購入者のみ・配布禁止など）を読んで、先生に伝える
- **問題を作る担当には、資料そのものを開かせない**。分析の結果（形式・数・論点の語）だけを渡す

## 手順
1. **受け取る**: 作業場所で展開 → `private/<名前>/` に移す → `pdftotext -enc UTF-8 -layout` で文字を取り出す（同じ場所に置く）
2. **分析する**（担当に出す。question-author）。結果は `private/<名前>/analysis.md` に（担当が .md を書けないときは、報告の本文を門番が保存する）
   - 総数、形式ごとの数と割合（正しいもの／適切でないもの／組み合わせ／具体例／計算 など）、形式ごとの作りの特徴（誤答の作り方）
   - 章（`<アプリ>/data/syllabus.json` の中項目）ごとの数
   - アプリの今の問題との比べ（形式・章・生成 AI などの題材）
   - アプリに無い論点の一覧（語だけ）
   - 問題を足す計画の案（章ごと・形式ごとの数）と、今のデータの形で表せない形式
   - 資料に問題文が無い（解答だけ）など、分析の限界も書かせる
3. **先生に計画を見せて決めてもらう**: 何問足すか、配分、今ある問題を書き換えるか（2026-10-09 は「200問足す・書き換えない」に決まった）
4. **データの形が足りなければ先に足す**（要件定義書の format → data.js → check-data の検査 → 画面の札。2026-10-09 は combo を足した）。形を崩した問題で検査が止まることを確かめる
5. **作る**（担当に出す。question-author を2〜3人、章のファイルが重ならないように分ける）
   - 指示に必ず書く: 資料は開かない／analysis.md だけ読む／question-author.md を全部読む／答えは一次情報で確かめて sources に書く／今ある問題と重複しない／今ある問題・カードは変えない／触ってよいファイル
   - 検査: check-data・check-answers-unchanged・npm test
6. **門番が確かめる**: 足した数と形式を数える。数問を自分で読む（噛み砕けているか・答えが一意か）。資料の文と似すぎていないかを、`private/<名前>/` の取り出した文との文字の重なり（長い同じ文字の並び）で機械で調べる
7. コミット → 公開（→ cert-quest-publish）
